How it works

Three layers before the model, and a switch to remove them

Risk enters at every stage, so the safeguard sits in front of the model rather than as one check at the end. Flip the guardrails off during the talk and the same request goes straight to the raw model.

1

Policy engine

Deterministic rules mapped to the four principles. They block, redact, or attach a required safeguard, and behave the same every time.

2

NeMo self-check

NVIDIA NeMo Guardrails asks a local Llama 3 model to judge anything the rules did not catch.

3

Guided model

Llama 3.1 answers with a clinical system prompt plus the safeguards the policy engine required.

✕

Guardrails off

The raw model with no policies, redaction, or system prompt. It's useful for showing what changes.

Policies

Six policies, traced to the talk's principles

Each policy names the principle it enforces, so the audience can follow a decision back to the slide that motivated it.

On versus off

What the audience sees in the live demo

Guardrails on

  • Identifiers are stripped before the model reads a case note.
  • Re-identification, hidden subgroup failures, and auto-signed notes are refused, and the model is never called.
  • Dosing answers are labeled decision support that needs clinician verification.
  • Deployment questions come back with an external-validation checklist.

Guardrails off

  • The raw model repeats the patient's name, MRN, date of birth, and SSN back.
  • It designs a cost-as-need triage score without a word about bias.
  • It still refuses some obviously harmful requests on its own. That shows why policy can't be left to the model alone.
Run locally

Run the full demo with a local model

The full app needs Python 3.10 or newer and Ollama. It runs entirely on your machine on macOS, Linux, or Windows.

# macOS or Linux
git clone https://github.com/bayegaspard/responsible-ai-healthcare-guardrails.git
cd responsible-ai-healthcare-guardrails
./scripts/setup.sh      # one time: packages, models (about 10 GB), tests
./scripts/run.sh        # then open http://127.0.0.1:5050

# Windows (PowerShell)
powershell -ExecutionPolicy Bypass -File scripts\setup.ps1
powershell -ExecutionPolicy Bypass -File scripts\run.ps1

Full steps, settings, and troubleshooting are in the README.
